# Phase 17 KuCoin-native data and labels

Approval **No validated model**. Execution **MANUAL_OUTSIDE_LAB**. Phase 17 uses public KuCoin data for local research. Existing collectors, studies, and paper books keep their own rules and schedules.

## Operator commands

Run from the project root in Windows PowerShell.

```powershell
.\phase17.ps1 status
.\phase17.ps1 report
.\phase17.ps1 enable
.\phase17.ps1 pause
.\phase17.ps1 disable
.\phase16.ps1 status
```

`enable` turns on the existing Phase 16 eligibility gate. The managed worker dispatches a qualified allocation after the profile interval and shared resource checks clear. `pause` pauses fitting and retains the campaign checkpoint and original clock. `disable` turns recurring training off. Collection, label qualification, and the Phase 15 books continue independently of these controls. Resume a paused job with `phase16.ps1 resume`. Use `phase16.ps1 report --campaign <campaign-id>` for a particular comparison.

Open **Native learning readiness** in the existing dashboard. It separates source rows, gaps, feature-ready decisions, eligible setups, mature labels, paper publications and fills, and native evaluation trades. Counts across Phase 15 books represent publication events. They supply no labels.

## Automatic operation

The existing scheduled KuCoin worker launches the authenticated public observer on its existing cadence. Phase 17 reads Phase 13 and Phase 14 futures receipts for shared coverage. After the protected funding closeout, that observer switches to separately budgeted 60-day XBTUSDTM shards. One managed BTC-USDT hourly request uses the same public client and retains its own receipt and request reservation. An access or rate limit stops the affected route.

After the theoretical feature warm-up, a bounded child qualifies closed UTC days with a two-hour receipt grace. It uses the existing one-job lock, two compute threads, 640 MiB RSS guard, two-hour deadline, and RAM, disk, and output safeguards. Same-cutoff retries reuse the original clock and completed artifacts. Phase 16 receives a sealed bundle at the registered cut or an ensuing seven-day cut that clears the floors. This registration allows one automatic allocation per eligible profile.

Phase 14 ends February 7, 2027 at 20:00 UTC. Its frozen evaluation sample is excluded from development labels. The extra day and UTC rounding were collection and funding-closeout scheduling choices. The pilot uses that same post-closeout native source boundary. The original Phase 17 allocation labels the in-study futures stream as shared coverage. Its raw receipts continue to serve Phase 14 and Phase 15 under their own registered rules. The pilot uses independent Phase 9/10 trade-candle receipts for feature initialization and excludes the Phase 14 seed and outcomes. A separately commissioned post-closeout collector bridge could recover some of the 28 hours between the Phase 14 horizon and the native shard start. It would need dated execution and settlement receipts and a separate allocation with its own causal availability.

The original registration computed `context_lower_bound` from the first UTC day and `context_days`. Day used ten days for a 51-bar four-hour dependency and completed decisions. Position used 147 days for two adjacent 20-week SMA windows, which span 21 closed weeks. Swing used 201 days for adjacent 200-day windows. The values were necessary lower bounds for a stream starting empty. The pilot preserves the features and admits separately checked monitoring bars for the same market and trade-price basis. Stored receipts retain their original times. Later admission cannot make an earlier decision timely. The bridge requires contiguous canonical buckets and parity with the operational feature implementation. Feature-only rows can initialize feature state but cannot provide decisions, fills, labels, or P&L. A gap limits dependent buckets and paths. It does not block a later contiguous context with sufficient history.

The original `phase17.labels.qualify` checks `first_cutoff` and then seven-day extensions. That gate blocks the original fit as well as its evaluation. The original dates came from context plus Day's 30 train, 14 inner, and 14 outer days, and Position's 75 train, 45 inner, and 60 outer days. Swing has zero added fold days. The pilot freezes the inner boundary at the first supervised daily cutoff with 35 mature training labels. It then needs ten strictly later mature inner labels, the profile's new-maturity floor and interval, and the shared resource admission. At most one pinned Ridge is fitted per eligible profile. The inner assessment measures that fixed hypothesis and makes no parameter choices. The fixed exit and receipt maturity rules still apply, including the conservative holding-path boundary check. Future setup counts determine when the floors clear.

A completed pilot fit automatically reserves a later independent forward window if the existing stream has enough remaining coverage. It starts on the next UTC day after the fit and last consumed receipt. The scheduled windows are 90 days for Day and 120 for Position, followed by two hours for receipts. The outer ten-label and 25-closed-trade floors still govern evaluation. The candidate, model version, costs, controls, stress assumptions and code are pinned.
