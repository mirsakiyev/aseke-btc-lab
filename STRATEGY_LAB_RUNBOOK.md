# Strategy Library and Research Lab

The sandbox runs on demand. Its execution mode is **MANUAL_OUTSIDE_LAB** and its model approval is **No validated model**. See [the architecture](STRATEGY_LAB_ARCHITECTURE.md) for ownership and data flow.

## Registry and inventory

`runs/strategy_lab/registry.sqlite3` holds immutable `strategy_version` snapshots, append-only `strategy_event` records, source attachments in `source_blob`, admitted `dataset` manifests, experiment `job` records with append-only `job_event` and `checkpoint` rows, and disabled `proposal` manifests. Each version binds a stable ID and family, version number, creation time, rules, parameters, market, sources, and implementation version. Change a frozen specification by supplying its latest hash to `stage --previous`. The replacement starts in `DRAFT`. Lifecycle reasons and evidence flags remain visible by version.

| Existing version seeded | Profile and original market | Variant |

| `phase15/swing/fixed` | Swing · KuCoin XBTUSDTM | Fixed R |

| `phase15/day/fixed` | Day · KuCoin XBTUSDTM | Fixed R |

| `phase16/day/initial-ridge` | Day · Binance BTCUSDT futures development | Fixed R + Ridge |

These seven entries belong to one breakout family. The Phase 15 snapshots include the original sealed registration and paper policy. Historical replay uses the existing one-bar IOC model with the rules-only signal. It does not reconstruct published quotes or the Phase 15 entry band, expiry, or paper ledger. Phase 16 entries reference the sealed initial catalog, trial, fold definitions, and available recorded outcomes. They are catalog entries for historical provenance. Their fitted models cannot run in this sandbox. A checkout missing the workstation's sealed sources reports them in `seed`.

## Import the first new strategy

The reviewed [EMA Pullback Trend Continuation](strategies/ema_pullback_trend_continuation/README.md) family has its own source reference and Position and Swing variants. Use `./strategy-lab.ps1 import-ema-pullback` to register and fixture-test those versions using the existing sandbox baseline snapshots.

1. Open **Workspace → Strategy Library / Research Lab → New Strategy** in Streamlit. Choose the profile and fill in the template. Give the hypothesis a stable family ID and give the profile or exit variant its own strategy ID. Reuse the entry recipe's family ID for a built-in variant. Include exact thresholds, indicator periods, entry and exit conditions, invalidations, UTC session, position sizing, and data dependencies.
2. Record the author, reference, and license status. An article URL needs a title and publisher. A local document, Pine reference, annotated chart, or repository file can be attached for provenance. Attachments up to 2 MiB are stored by hash. References can identify larger local documents. Import leaves a draft for human or Codex-assisted review. Uploaded files and URLs are treated as reference material.
3. Resolve the validator's missing, discretionary, conflicting, or unavailable rules before recording `SPECIFIED`. The validator flags common future-data and repainting markers. Review source logic, indicators, and timing explicitly, since text checks cannot prove causality. The built-in implementation supports `breakout_v1`, `pullback_v1`, and `range_reversion_v1` with `fixed_r_v1` or `atr_trail_v1`. A different hypothesis starts as a draft and needs reviewed evaluator code and tests. `recipes` shows the supported formulas and required parameter names. For a new built-in recipe version, use the matching rule text and the stop text generated by `recipe_description` in `lab/strategy_lab/specification.py`.
4. Run the version test, then review the development data and submit one explicit historical request. The request pins the tested code, runtime, strategy, risk, costs, data, baseline, intervals, and stress settings.

```powershell
.\strategy-lab.ps1 seed
.\strategy-lab.ps1 list
.\strategy-lab.ps1 show <version-hash>
.\strategy-lab.ps1 recipes
.\strategy-lab.ps1 template position | Set-Content -Encoding utf8 draft.json
.\strategy-lab.ps1 validate draft.json
.\strategy-lab.ps1 stage draft.json
.\strategy-lab.ps1 stage revised.json --previous <version-hash> --source-file C:\intake\reference.pine
.\strategy-lab.ps1 export-source <attachment-sha256>
.\strategy-lab.ps1 state <version-hash> SPECIFIED --reason "Reviewed exact rules and source assumptions"
.\strategy-lab.ps1 test <version-hash>
```

## Admit historical data

Provide an explicitly approved, locally exported KuCoin **development-only** bundle in a directory outside the repository. Use data with independently verified provenance and a license or permission suitable for research. The lab checks the file identities and date partition. The operator attests that the export contains no sealed holdout, Phase 14 evidence, Phase 15 observations, or Phase 17.1 inputs. The sandbox has no feed acquisition path. Its exclusive data cutoff is 2025-11-08 00:00 UTC or an earlier configured holdout start.

The UTF-8 bundle JSON must contain the following fields.

| Field | Content |
| --- | --- |
| `profile`, `venue`, `market`, `instrument`, `native_seconds` | `position`, `KuCoin`, `SPOT`, `BTC-USDT`, `3600`; or `swing` / `day`, `KuCoin`, `FUTURES`, `XBTUSDTM`, `60` |
| `use`, `start`, `end_exclusive` | `DEVELOPMENT_ONLY` and aligned timezone-aware boundaries |
| `provenance` | `reference`, `license`, `origin`, and `exclusion_attestation` |
| `availability` | `RECORDED_RECEIPT` or explicitly modeled `HISTORICAL_CLOSE_PROXY` |
| `assets` | `trade` and, for futures, independent `mark` objects with relative `file` and `sha256` |
| `contract` | `reference`, `effective_from`, `effective_until`, and `terms` covering the entire dataset |
| `funding_schedule`, `funding` | For futures, contiguous sourced segments with `start`, `end_exclusive`, `anchor`, `interval_minutes`, `reference`. Settlements in UTC order with `settlement_at`, `received_at`, `rate`. Optional `funding_tolerance_seconds` is less than one native bar. |

Trade Parquet requires `open_at`, `close_at`, `open`, `high`, `low`, `close`, and `volume`. The mark file uses the same clock and OHLC fields. Receipt mode requires UTC `received_at` on both bases. Contract terms require `family` (`spot` or `linear_perp`), `quote` (`USDT`), `base_per_contract`, `quantity_step`, `price_tick`, `min_contracts`, `tier_notional`, `max_leverage`, `maintenance_rate`, and `liquidation_fee_rate`. Funding rates must correspond one-to-one to the evidenced schedule. A published zero is a valid settlement. Missing settlements block admission.

```powershell
.\strategy-lab.ps1 admit-data C:\intake\development.json --approve "Operator name"
.\strategy-lab.ps1 datasets
.\strategy-lab.ps1 evaluate <version-hash> <dataset-hash> <decision-utc> --as-of <availability-utc>
.\strategy-lab.ps1 request <version-hash> <dataset-hash> --development <start-utc> <end-utc> --validation <start-utc> <end-utc> --approve "Operator name"
.\strategy-lab.ps1 run-next
.\strategy-lab.ps1 jobs
.\strategy-lab.ps1 status <job-hash>
.\strategy-lab.ps1 logs <job-hash>
.\strategy-lab.ps1 cancel <job-hash>
.\strategy-lab.ps1 resume <interrupted-job-hash>
.\strategy-lab.ps1 compare <job-hash> <other-job-hash>
.\strategy-lab.ps1 export <job-hash> --save
```

## Indicators, replay and comparison

The shared indicators include completed higher-timeframe SMA, EMA26, RSI14, MACD and histogram, ATR14, prior Donchian highs and lows, relative volume, confirmed pivots, Fibonacci 61.8%, returns, realized volatility, Bollinger 20/2, and an intraday UTC-day candle-weighted VWAP proxy. See `recipes` for the calculation and warmup definitions. Tick VWAP, historical depth, and finer execution ordering require separately supported evidence.

Warmup can use admitted history preceding either observation period. Development and validation intervals are chronological, non-overlapping and separately funded. The validation volatility stress threshold comes from development. Completed bars arriving after their fixed decision allowance are omitted, so later receipts cannot revise earlier signals. The existing 15-minute futures capture cycle can deliver one-minute bars with receipts minutes after close. Treat close-time proxy results as hypothetical even when the path is otherwise complete.

Spot and futures use separate existing executors, with a common rules-only baseline sized at the candidate's risk and cost assumptions and a flat cash reference. The simulator includes adverse fills, fees, mark-based futures triggers, trade-price exits, settled funding, isolated margin and fixed-tier liquidation. Stresses cover double costs, delayed entry and exit, additional adverse prices, a missing observation, and high-volatility entries. Futures adds mark divergence and adverse funding. If a gap, ambiguity, missing warmup, or unresolved exposure invalidates the economic path, period return and expectancy are withheld. The dashboard shows historical equity curves only for complete accounting.

**Research Comparison** requires identical dataset, periods, baseline, runtime, risk, costs and simulation assumptions. It displays sample size, net expectancy in USDT and R, win rate, profit factor, drawdown, exposure, turnover, costs, funding and stress results. Sharpe and Sortino require at least 30 daily returns, at least 20 nonzero days, and a defined denominator. Exploratory ordering requires at least 25 closed trades in each relevant case, complete accounting, adequate baseline and stress results, and a positive lower block-bootstrap expectancy bound. The lab uses the existing monthly estimate when eight months with trades are available. Its weekly fallback uses blocks of at least three weeks and at least twice the maximum holding horizon, with at least 12 trade weeks and four blocks. The sandbox counts all registered requests by profile, including unsuccessful and cancelled attempts. Intervals are descriptive and unadjusted for selection across trials. The result remains exploratory even if a candidate clears the screen.

## Resource limits and operating boundaries

- At most 12 active requests, one worker, one compute thread and no GPU requirement. The supervisor checks a 640 MiB worker RSS ceiling, 600 CPU seconds per attempt, 900 elapsed seconds from first execution, 1,250 MiB available host RAM and 2 GiB free disk. It uses the existing shared research locks.
- Up to 450,000 native rows per dataset, 48 MiB per Parquet asset, 384 MiB of staged dataset files, 64 MiB of reference attachments, 2 MiB per checkpoint, 512 MiB for the sandbox and 2,500 proposals per case.
- `run-next` is foreground and processes one request. Completed stages persist across interruption. `resume` requeues within the original deadline and three-attempt limit. Cancellation keeps completed checkpoints. Exact duplicate requests reuse their original identity.
- Streamlit renders registry and checkpoint reads. Saving a draft or a disabled proposal requires a form submission. Start historical replay from the CLI. Completed JSON exports are under `runs/strategy_lab/exports`.
- Initial scope includes built-in rules-only hypotheses and historical OHLC-based economics. It does not simulate tick execution, market depth, or cross-margin and changing maintenance tiers. The sealed historical catalog and existing paper books have their own policies.

## Prospective review

After reviewing a qualifying screen, explicitly record `HISTORICAL_RESEARCH` and `SHORTLISTED` with reasons. **Prospective Experiment Proposal** previews the frozen version and checks eligibility. Supply a future UTC-aligned start, horizon, minimum closed trades, execution model, and a data-availability contract with source, receipt rule, gap policy and economic path. The manifest records a standalone hypothetical account and comparison benchmark. Operator review can record `REVIEWED`, `CHANGES_REQUESTED`, or `DECLINED`. The manifest remains **DISABLED / AWAITING_EXPLICIT_APPROVAL**.

```powershell
.\strategy-lab.ps1 preview-proposal <version-hash> <job-hash>
.\strategy-lab.ps1 propose <version-hash> <job-hash> proposal.json
.\strategy-lab.ps1 proposals
.\strategy-lab.ps1 review-proposal <proposal-hash> REVIEWED --operator "Operator name" --reason "Reviewed receipt and risk contract"
```

## Verification

`python -m pytest tests/test_strategy_lab.py -q -s` includes an isolated Spot experiment with chronological windows and eight replay cases. The test verifies accounting parity with an equivalent rules-only baseline, withheld return in the missing-data case, experiment identity reuse, restart bookkeeping and a disabled prospective preview. It also tests futures mark/trade separation and settlement handling. Synthetic data and test artifacts stay in temporary directories.
